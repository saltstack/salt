Fixed ``file.replace`` and other ``file`` module functions mishandling files with CRLF line endings. ``.*`` and ``\s*`` no longer swallow the ``\r`` of a CRLF terminator, so a ``file.replace`` state no longer rewrites a Windows file on a second run just to strip its carriage returns, and ``$`` now matches at the end of a CRLF terminated line in ``file.replace``, ``file.search``, ``file.comment_line`` (and ``file.comment`` / ``file.uncomment``), ``file.contains_regex`` and ``file.line``. ``append_if_not_found``/``prepend_if_not_found`` in ``file.replace``, ``file.append`` and ``file.prepend`` now follow the line endings already used by the file instead of always using ``os.linesep`` or ``\n``. ``file.write`` is intentionally unchanged: it replaces the whole file and always terminates each string with ``\n``. Patterns that explicitly reference ``\r`` keep their previous behavior.
