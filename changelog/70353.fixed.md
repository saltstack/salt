Fixed a minion deadlock in ``zmq_ctx_term()`` after a master outage (#70353).
``SyncWrapper.close()`` now drains its pending tasks from a helper thread
when it is called while another event loop is running in the same thread,
so the ZMQ sockets held by those coroutines (e.g. ``AsyncAuth._authenticate``
suspended in ``RequestClient.close_async``) are actually closed instead of
being left pending. ``RequestClient`` additionally tracks the sockets it
creates in a strong-ref list on the instance, so the ``weakref.finalize``
context teardown can close them deterministically and ``context.term()``
returns on the calling thread without a daemon-thread workaround.
