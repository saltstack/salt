Added opt-in memory-headroom backpressure for the master's ``EventPublisher`` and pooled ``MWorkerQueue`` subprocesses. Four new master config options (``event_publisher_memory_headroom``, ``event_publisher_memory_max``, ``mworker_queue_memory_headroom``, ``mworker_queue_memory_max``) accept a percentage string (``"5%"``) or an absolute size (``"500M"``, ``"5G"``, int bytes). When set, the reference "total memory available" is resolved from the config override, then cgroup v2, then cgroup v1, then ``psutil.virtual_memory().total`` -- matching the minion-side pattern from ``minion_memory_headroom`` (#69884). ``EventPublisher.publish_payload`` awaits an ``asyncio.Event`` gate that a ``PeriodicCallback`` toggles based on the check; ``MWorkerQueue``'s pooled dispatch loop skips ``recv_multipart`` on ROUTER when the check fails so ZMQ RCVHWM propagates backpressure to peers. Non-pooled ``zmq_device`` is a C-level ``zmq.device(QUEUE)`` proxy with no Python hook point and logs a warning that the opts have no effect there. Helpers extracted to a new module ``salt.utils.memory`` so the minion path (#70038) can consolidate on the same code in a follow-up.
