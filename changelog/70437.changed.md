TLS clients on the ``tcp``/``ws`` transports now verify the master certificate against the configured ``master`` hostname instead of the resolved IP address (an IP SAN is only needed when ``master`` is an IP literal), and the new ``ssl.server_hostname`` option pins the expected name for master-local clients or load-balanced setups. Enterprise certificates with DNS-only Subject Alternative Names no longer fail with ``IP address mismatch``. Deployments whose master certificate carries only an IP SAN while minions use a hostname must set ``ssl.server_hostname`` to that IP or reissue the certificate.
When ``ssl.ca_certs`` or ``ssl.verify_locations`` is configured those CAs are now the only trust anchors; the system/certifi trust store is no longer loaded in addition, so a publicly trusted CA can no longer issue a certificate that a minion accepts as the master.
