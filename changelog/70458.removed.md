Removed deprecated ``salt.modules.x509_v2`` behavior that was scheduled for removal in 3009.0 (Potassium):

- ``create_certificate``: ``algorithm`` (use ``digest``), ``text``, ``version``, ``serial_bits``. Default ``days_valid`` changed from 365 to 30.
- ``create_csr``: ``algorithm`` (use ``digest``), ``text``, ``version``.
- ``create_crl``: ``text`` is no longer accepted. Default ``days_valid`` changed from 100 to 7. The ``{<key>: [<dict>, ...]}`` wrapper for ``revoked`` entries and the top-level ``reason`` key are no longer accepted; use a flat list of dicts and specify the revocation reason via ``extensions:CRLReason``.
- ``create_private_key``: ``bits`` (use ``keysize``), ``cipher``, ``verbose``, ``text``.
- ``get_public_key``: ``asObj``.
- ``get_signing_policy``: long-form name attributes (e.g. ``commonName``) and long-form extensions (e.g. ``X509v3 Basic Constraints``) are no longer auto-aliased; signing policies must use short names (``CN``, ``basicConstraints``).
- Long-form name attributes and extensions passed as keyword arguments to ``create_certificate`` / ``create_csr`` are no longer auto-aliased; use the short names.
