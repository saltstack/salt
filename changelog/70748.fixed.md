Reduce flock contention during bulk resource-registry writes. ``MmapCache.put_many`` now supports yielding the write lock every ``resource_registry_put_many_yield`` entries (default 1024) within a batch, so concurrent writers on the same cache file (e.g. peer-replicated registers in a master cluster) interleave fairly instead of stacking up behind a multi-second flock hold. End-of-batch fsync + index flush is unchanged, so happy-path throughput is preserved.
