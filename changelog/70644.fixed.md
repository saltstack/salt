Fix `topology link_manager._handle_master_auth` incrementing `session_generation` on every call, which caused frames from nodes 2..N of a multi-master peer cluster to fail `_verify_session` after the first peer-cluster node authed (each cluster-node independently authenticates against the same `origin_cluster_id`, so bumping on every auth left earlier nodes pinned to a stale gen). The handler now keeps the generation stable across re-auths and returns `session_generation` in the reply so the sender's `PeerMasterLink._rotate_session` can pin its counter to match.
