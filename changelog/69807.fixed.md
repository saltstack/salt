Fixed ``salt-minion`` self-upgrade via ``pkg.installed`` crashing the state run with ``ModuleNotFoundError: spec not found for the module 'site'``. On a minion-driven upgrade of ``salt-minion`` / ``salt-common``, the relenv onedir tree at ``/opt/saltstack/salt/lib/python<VER>/`` is replaced on disk by dpkg/rpm while the running Python interpreter is still holding its old ``sys.path``. ``salt.state.State.module_refresh``'s ``importlib.reload(site)`` then failed to find ``site.py`` on disk and raised ``ModuleNotFoundError``, which was not caught and killed the state run. ``module_refresh`` now catches ``ImportError`` in addition to ``RuntimeError``/``TypeError``, and ``check_refresh`` skips the in-process module reload entirely when a ``pkg.installed`` change reports that a salt package (``salt``, ``salt-common``, ``salt-minion``, ``salt-master``, ``salt-api``, ``salt-syndic``, ``salt-cloud``, ``salt-ssh``) was installed or upgraded. The documented FAQ ``cmd.run bg: True`` pattern remains responsible for restarting the ``salt-minion`` service after the state run completes.
