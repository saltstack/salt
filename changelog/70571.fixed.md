Fix ``salt.topology.migration.promote_solo_to_clustered`` crashing with ``AttributeError: 'NoneType' object has no attribute 'propose'`` on every topology master restart with existing registry state. The publish daemon schedules ``link_manager.start`` before it finishes constructing the ``RaftService`` (founder path defers Raft startup by ``cluster_join_timeout``; learner path waits for a join-reply), so the migration step ran with ``raft_service=None``. The migration now detects that case, logs INFO, and returns — the on-disk committed Raft log is replayed by ``RaftService.__init__``'s ``apply_entries`` call (via the persisted ``commit_index`` in ``state.p``) which converges the state machine from disk without the extra propose round. The daemon also now hands through its current ``self._raft_service`` so masters resuming on an already-joined cluster get the immediate propose path too.
