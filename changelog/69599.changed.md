``pillar_mask_output`` now defaults to ``False``. The ``pillar`` execution module functions always return the real values and the ``unmask`` argument no longer has any effect. When the option is set to ``True``, pillar containers are redacted where they are output (minion job returns, CLI output, ``repr()`` and logging) instead of when a function returns them. Explicitly hidden containers and states with ``no_log: True`` continue to redact independently of this option.
