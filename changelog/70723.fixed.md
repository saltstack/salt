Master-side resource register chunks now stream directly into the registry stamped with the register's Salt jid instead of accumulating in a per-worker staging dict; the master runs the stale-entry sweep inline when ``_chunk_is_last=True`` arrives on the terminal chunk. Removes an O(chunks) in-memory accumulator per master worker that caused multi-GB RSS and MWorker stalls under concurrent large-minion registration. Wire-protocol bump: chunked registers now carry ``_register_jid`` on every chunk (replaces ``_RegisterChunkStage``-era keying). Rolling-upgrade guidance for mixed-version 3008.x clusters: roll masters first — older masters still run the pre-fix ``_RegisterChunkStage`` scatter-vulnerable code; newer minions talking to older masters will be registered via that broken path until the master catches up. In isolated-FS cluster mode chunks scatter across different masters behind haproxy; the terminal-chunk sweep only runs on the master that received it, so other masters hold un-swept entries until the next register (follow-up: sticky routing or cluster-sync forwarding).
``Minion.pillar_refresh`` no longer implicitly re-registers resources. Operators who need the resource registry to reflect a pillar change must explicitly chain ``saltutil.refresh_resources`` after ``saltutil.refresh_pillar`` (unix-style: one command, one job). ``saltutil.refresh_resources`` gains ``wait=True`` + ``timeout`` parameters that block on the new ``MINION_RESOURCE_REFRESH_COMPLETE`` event, mirroring ``saltutil.refresh_pillar``.
Register jids are now generated with ``unique_jid=True`` (monotonic within a process via ``LAST_JID_DATETIME``, disambiguated across processes via ``_<pid>`` suffix) and persisted to ``<cachedir>/.last_register_jid`` on the minion so subsequent process incarnations start past any prior-session jid. Protects the sweep's strict-``<`` invariant against two registers in the same microsecond AND against NTP backward-steps / container-snapshot restores where wall clock rolls back.
Resource-register chunk sends now use a dedicated ``resource_register_chunk_timeout`` (default 60 s) instead of ``return_retry_timer``. A master-side sync commit of a full ``resource_register_chunk_size=16000`` chunk was observed at ~10-13 s on slower runners, exceeding the 5-10 s ``return_retry_timer`` window; the minion then retried the same chunk against different MWorkers and gave up with only the first chunk committed. The chunk-send timer is now independent of the return-ack timer.
