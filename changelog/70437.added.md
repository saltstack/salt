Added ``ssl.client_certfile`` and ``ssl.client_keyfile`` so the master (or a minion) can present a dedicated ``clientAuth`` certificate on outgoing TLS connections while ``certfile`` stays a ``serverAuth``-only certificate.
Rotated TLS certificates (``ssl.certfile``/``keyfile``/``client_certfile``/``ca_certs``/``verify_locations``) are now picked up by running masters and minions without a restart (``ssl.reload_interval``, default 60s; clients also re-check before each connection). New material is validated first: the pair must load, the certificate must be time-valid and, when verification is enabled, chain to the configured trust anchors (``ssl.reload_verify_chain: False`` skips the chain check for split-PKI deployments); otherwise it is rejected and the current certificate stays in use.
