Fixed mutual TLS (``ssl`` with ``cert_reqs: CERT_REQUIRED``) on the ``tcp`` and ``ws`` transports when worker pools are enabled (the 3008 default): the pool router wrapped its local IPC hop to the MWorkers in TLS, so every encrypted request failed with ``WRONG_VERSION_NUMBER`` and minions never got past authentication.
Fixed the TCP transport connecting to masters that resolve to an IPv6 address (``TypeError: AF_INET address must be a pair``), fixed ``PubServerChannel`` losing ``aes_funcs``/``presence_events`` when the publish daemon is started with the ``spawn`` or ``forkserver`` start method, and stopped logging every request's client certificate at ERROR level.
Fixed the tcp transport clients under concurrent use: ``connect()`` is serialized so concurrent sends no longer open duplicate (TLS) streams; a send that lands while the stream is reconnecting waits for the new stream instead of being silently dropped (seen as "File client timed out" during highstates), and a write that fails is reported to the caller (never re-sent, so no duplicate delivery) rather than left to hang; and ``RequestClient`` no longer uses the request stream, reader task or in-flight connection a forked job child inherits from the minion.
Fixed a cancelled ``RequestClient`` reader task surviving its own cancellation: the CancelledError was swallowed, the reader's next read failed with ``AssertionError: Already reading`` and the generic exception handler restarted it with a close and reconnect, so it reconnected forever and a drain waiting for it never completed. The reader now ends on cancellation; when something other than ``close()`` cancels it, pending requests fail at once and the next send reconnects with a new reader. ``disconnect_callback`` is awaited when it is a coroutine.
