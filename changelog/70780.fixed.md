  completion sentinel's `expected_peers` from joined peers only; track
  per-peer eofs on the sentinel so a straddler peer cannot false-complete

- NEW-6 / NEW-7a: apply the same handshake gate to `cluster.sync_roots`
  and multi-ring runner fan-outs with `pending_event=None` so un-joined
  peers skip with a WARN and catch up via state-sync (sync_roots) or
  Raft log replication (multi-ring).
- NEW-9: periodic steady-state `pending-flush` sweep on the publish
  daemon (`cluster_cache_replicate_pending_sweep_interval`, default 2 s)
  drains stranded queues for peers that joined without a subsequent
  handshake event.  A per-peer `asyncio.Lock` serialises the sweep
  drain against live publishes so "live wins over stale" is preserved
  under last-writer-wins.
- D-1b: `PendingEvent` carries a `cluster_aes_fp` fingerprint stamped at
  encrypt time.  The flush path compares against the current fp and
  drops mismatches (or any `<unavailable>` sentinel) with a loud WARN
  so a rotation that races the encrypt+enqueue window no longer causes
  silent `Failed to decrypt` on the peer.
- NEW-4: plain `threading.Lock` around `_cache_bank_barriers` makes the
  check-then-act in `_handle_delegate_cache_write` atomic against
  concurrent `_release_cache_bank_barrier` / `_drain_cache_bank_barrier`
  on the event-loop thread.  The drain uses snapshot-under-lock-then-
  release so the lock stays non-reentrant.
