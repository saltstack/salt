Fixed ``AsyncAuth.authenticate()`` leaving the shared sign-in task half
cancelled when the caller that gave up was the last waiter. Cancelling the
task is cooperative, and a caller that stops its event loop as soon as it is
released could leave the task ``cancelling`` with its REQ socket still open;
the next ``gc.collect()`` then blocked forever in ``zmq_ctx_term()``,
freezing the minion. The last-waiter cancel path now closes the sign-in
task's request channel synchronously so the socket and zmq context are
released before the caller resumes.
