Fixed `salt-pip` leaking the parent process's `PYTHONPATH` into the pip subprocess it spawns. `salt-pip` now always runs pip with `PYTHONPATH` set to only salt's own `extras` directory, isolating it from the rest of the system as documented. Previously an inherited `PYTHONPATH` pointing at an unrelated Python installation was prepended onto `extras` rather than replaced, so pip (especially with `--force-reinstall`) could find and uninstall packages belonging to that unrelated environment.
