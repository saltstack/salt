Fix topology-only master Windows spawn: ``populate_secrets`` no longer allocates the ``cluster_ready`` ``multiprocessing.Event`` when ``cluster_id`` is set but ``cluster_peers`` is empty. The Event was dead code in that configuration (``should_serve_requests`` short-circuits True without consulting it) and could not survive ``MWorker.__getstate__``'s plain-pickle round-trip on Windows ``multiprocessing.spawn`` -- SemLock handles only duplicate via ``Process(args=...)``, not pickle -- so every spawned MWorker crashed with exit 1 before logging was initialised, leaving minion authentication REQs timing out forever.
