Fix "Master did not return a session key for pillar request" on master clusters with ``cluster_isolated_filesystem: True`` behind an L4 load balancer. Session keys are now derived deterministically from ``cluster_aes`` via HKDF-SHA256 when the cluster runs with isolated filesystems, so every peer master computes the same per-minion key without replicating ``cachedir/sessions/<minion>``. Rotation stays in lockstep with ``cluster_aes``. Standalone masters and shared-filesystem clusters keep the existing random-file behavior.
