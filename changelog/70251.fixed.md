Fixed ``state.orchestrate`` overwriting the master's ``user`` option with the user that started the orchestration. This made ``salt.runner`` and ``salt.wheel`` steps on a root master drop privileges to a salt-api eauth user, and made master-side code that reads ``user`` during an orchestration (``reactor.list``, ``file`` state ownership defaults) use the wrong user. Inside an orchestration ``opts['user']`` is now always the master's configured user. A root process that runs ``state.orchestrate`` through the Python API with a non-root ``user`` in the master config now runs its ``salt.runner`` and ``salt.wheel`` steps as that user, as ``salt-run`` does.
