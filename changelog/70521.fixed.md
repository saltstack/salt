Fix topology peer handshake wedging at `configured`/`pending` on
clustered 3008.x masters.  Four narrowly-scoped fixes land together:

- `salt.topology.link_manager._masters_subdir` now resolves `masters`,
  `masters_pre`, `masters_rejected`, `masters_denied` against
  `cluster_pki_dir` when `cluster_id` is set (falling back to `pki_dir`
  for solo masters), matching the pattern used in
  `salt.master.Maintenance` and `salt.channel.server`.  The topology
  module was the only receiver that looked only at `pki_dir`, so
  pre-accepted peer keys seeded under `cluster_pki_dir/masters/` were
  invisible and every handshake returned `status=retry`.
- `salt.topology.link.PeerMasterLink.connect` now carries the master's
  identity public-key bytes (`cluster_pki_dir/cluster.pub` on
  clustered, `pki_dir/master.pub` on solo) in the
  `topology/_master_auth` load, so the receiver's pending-key sentinel
  at `masters_pre/<cluster_id>.pub` lands as the sender's actual key
  instead of a zero-byte file.
- `salt.topology.link_manager._open_inbound_listener` zeros
  `cluster_peers` in the inbound topology `ReqServerChannel`'s
  channel-opts dict so
  `salt.channel.server._cluster_is_ready` short-circuits True.  The
  topology handshake is a key-on-disk identity exchange that must work
  before Raft commits (startup) and through Raft flaps; without this
  bypass the receiver's gate replied `cluster_retry` to every inbound
  `topology/_master_auth` on a 3-master cluster.
- `salt.topology.link.PeerMasterLink.connect` and
  `salt.topology.link_manager._reconnect_loop` tolerate the
  `cluster_retry` wire envelope and recover provisional-key links in
  `DISCONNECTED`/`PENDING_ACCEPT` state, so a startup-race first-pass
  handshake failure no longer wedges a link until master restart.
- `salt.runners.topology._pki_dir` mirrors the same `cluster_pki_dir`
  resolver so `topology.peers` surfaces the correct `attached` state
  for clustered masters.
