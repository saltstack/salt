Defer heavy imports out of the minion daemon baseline.  On a Linux ``salt-minion`` this removes ``salt.master`` (imported unused by ``salt.transport.tcp``), ``salt.utils.master`` (imported unused by ``salt.pillar`` and imported only for the master-role branch of ``salt.utils.schedule``), ``salt.state`` (imported only for two onfail helpers in ``salt.utils.state``), three unused imports in ``salt.modules.mine``, the ``requests`` / ``certifi`` HTTP transitive chain in ``salt.utils.http`` (only needed for ``backend="requests"``), and the Windows-only helper modules ``salt.utils.win_dacl`` / ``salt.utils.win_reg`` / ``salt.utils.win_chcp`` / ``salt.utils.win_functions`` / ``salt.utils.win_network`` from ``salt.utils.atomicfile`` / ``salt.modules.cmdmod`` / ``salt.utils.args`` / ``salt.syspaths`` / ``salt.utils.parsers`` / ``salt.utils.user`` / ``salt.utils.network``.  Every deferred import is moved to the guarded scope of its actual call site (role check, platform check, or opt-in backend).  Paired A/B on a running 3008.x minion (Python 3.14 onedir) drops VmRSS from 75.3 MB to 63.8 MB (~11.2 MB, -15%) and cgroup ``memory.current`` from 111 MB to 92 MB (~18 MB, -17%) at daemon start.
