Stopped embedding the master's own config (`__master_opts__`) in the relenv minion config shipped to `salt-ssh` targets. It was master-side-wrapper-only data that nothing on the remote target ever read, and since the underlying master opts object is mutated across nested `Single`/wrapper calls during a single state run, embedding it caused the (otherwise fixed-size) minion config to grow unbounded until it exceeded the kernel's `ARG_MAX`, failing with `Argument list too long`.
